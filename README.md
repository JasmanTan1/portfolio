# jasmantan.com — portfolio & résumé

A static personal site. No framework, no dependencies, no server. `node build.mjs` reads the
content in `src/data.mjs` and `content/resume.md` and writes a complete site to `dist/`.

## Quick start

```sh
node build.mjs        # or: npm run build   -> writes dist/
node serve.mjs 5193   # or: npm run serve   -> http://127.0.0.1:5193
npm run pdf           # regenerate static/resume.pdf (only after editing the résumé)
```

Node 18+. There is nothing to `npm install` — `package.json` has no dependencies and exists only
to hold the scripts.

## Layout

```
build.mjs            the whole build: templates + page assembly
serve.mjs            loopback static server, for checking dist/ locally
src/data.mjs         ALL site content — hero, projects, skills, experience, contact email
src/markdown.mjs     tiny Markdown renderer used for the résumé page
content/resume.md    the résumé, in Markdown (the source of truth for /resume/)
static/              copied verbatim into dist/: styles.css, main.js, favicon.svg, og.png
tools/og.html        canvas that draws the 1200x630 link-preview image
tools/make-og.mjs    one-off helper that renders tools/og.html and saves static/og.png
tools/make-pdf.mjs   prints dist/resume/ to static/resume.pdf with the local Chrome
.github/workflows/   deploy.yml — builds and publishes dist/ to GitHub Pages
dist/                build output (gitignored — regenerate with `node build.mjs`)
```

### What the build produces

| Path | What |
|---|---|
| `index.html` | The portfolio: hero, selected work, home-server section, skills, experience, education |
| `resume/index.html` | The résumé, rendered from `content/resume.md`, with a print stylesheet |
| `resume.pdf` | The résumé as a 2-page A4 PDF, printed from the page above |
| `resume.md` | The Markdown résumé, downloadable |
| `404.html` | Not-found page (GitHub Pages serves this automatically) |
| `og.png`, `favicon.svg` | Link preview image and icon |
| `sitemap.xml`, `robots.txt` | |
| `CNAME` | `jasmantan.com`, for GitHub Pages custom domains |
| `.nojekyll` | Stops GitHub Pages running Jekyll over the output |

## Editing content

Almost everything lives in **`src/data.mjs`** — projects, skills, experience, the hero copy.
Rebuild after any change.

**Contact email** is the constant `CONTACT_EMAIL` at the top of `src/data.mjs`. It feeds the hero
button, the footer, the résumé CTA *and* the rendered résumé page — the build rewrites whatever
address is in `content/resume.md` to match it, so the site can never show two different addresses.
When `hello@jasmantan.com` is routing, change that one line, rebuild, redeploy.

## The résumé PDF

There is one source of truth: `content/resume.md`. From it the build renders `/resume/`, and
`static/styles.css` has an `@media print` block that turns that page into a clean A4 document —
navigation, footer, theme toggle and all colour dropped, type at 10.5pt, headings kept with the
content that follows them, list items never split across pages.

`static/resume.pdf` is that same page, printed. It is **committed**, and regenerated by hand:

```sh
npm run pdf      # build -> print to PDF -> build again so dist/ picks it up
```

`tools/make-pdf.mjs` serves `dist/` on a loopback port and drives the Chrome (or Edge) already
installed on the machine with `--headless=new --print-to-pdf --no-pdf-header-footer`. **No npm
dependency and no bundled Chromium** — that was the point. If no browser is found, or Chrome fails,
or the result looks empty, the script warns and exits 0 rather than failing the build; the build
then omits the download button and `/resume/` falls back to its **Print** button, which does the
same job through the same stylesheet. So the link on the site is never dead.

Because the PDF is committed, the GitHub Actions runner never needs a browser — it just copies the
file. **Re-run `npm run pdf` whenever `content/resume.md` changes**, or the PDF will lag the page.
(The workflow's build check fails if `dist/resume.pdf` is missing, but it cannot tell you the
contents are stale.)

Manual alternative, if you'd rather: open `/resume/`, Ctrl+P, "Save as PDF", *Headers and footers*
**off**.

The Markdown source is also published at `/resume.md` for anyone (or any parser) that wants it raw.

## Regenerating the link-preview image

`static/og.png` is committed. To change it, edit the canvas drawing in `tools/og.html`, then:

```sh
node tools/make-og.mjs     # then open http://127.0.0.1:5194/ once
```

It renders the canvas in a real browser (for the font rasteriser), posts the PNG back, writes
`static/og.png` and exits. Nothing about this runs in production or during `npm run build`.
Keep it well under ~200 kB — flat shapes compress, gradients do not.

## Deploying

The output is plain static files with absolute root-relative paths (`/styles.css`, `/resume/`), so
it must be served from a **domain root**, not a sub-path.

### GitHub Pages (this is the target)

`.github/workflows/deploy.yml` already does the work: on every push to `main` it checks out, sets
up Node 20, runs `node build.mjs`, asserts every expected file exists and is non-empty, then
publishes `dist/` with `actions/deploy-pages`. There is nothing to install, so a run takes seconds.

1. Create `JasmanTan1/portfolio` on GitHub and push `main`.
2. **Settings → Pages → Build and deployment → Source: GitHub Actions.** (Not "Deploy from a
   branch" — the workflow uses the Pages artifact API, which needs this setting.)
3. Settings → Pages → Custom domain: `jasmantan.com`. `dist/CNAME` is written by the build, so the
   setting survives every deploy. Tick **Enforce HTTPS** once the certificate is issued.
4. In Cloudflare DNS for `jasmantan.com`, replace whatever the apex points at with the four GitHub
   Pages A records — `185.199.108.153`, `185.199.109.153`, `185.199.110.153`, `185.199.111.153` —
   and a `CNAME www → jasmantan1.github.io` if a `www` alias is wanted. **Set these to
   DNS-only (grey cloud) until GitHub has issued the certificate**, then proxying can be turned
   back on; Cloudflare's proxy in front of an unissued Pages cert is the usual cause of a stuck
   "certificate provisioning" state.
5. `jasmantan1.github.io` is a separate existing Pages site and stays as it is — it is a
   *user* site and does not conflict with this *project* site holding the apex domain. Just make
   sure the apex A records are no longer pointing anywhere else.

The site lives entirely on GitHub's CDN, so it stays up when the mini PC is off — which is the
whole reason for choosing Pages over the tunnel.

### Alternative — the existing Cloudflare Tunnel (mini PC)

Serve `dist/` the same way Kubrix is served — a static server on a loopback port, with an ingress
rule in `~/.cloudflared/config.yml` above the catch-all:

```yaml
  - hostname: jasmantan.com
    service: http://127.0.0.1:<port>
```

then `cloudflared tunnel route dns mini-pc jasmantan.com`, and register a logon scheduled task the
way the other `HomeServer-*` tasks are set up. Pick a port that isn't already taken
(8090/8091/8765–8768/3000 are in use).

Whichever option: `dist/404.html` needs the server to serve it on a miss. `serve.mjs` does;
GitHub Pages does; a bare `python -m http.server` does not.

## Notes on the content

- Every claim on the site traces back to a repo or the résumé. Nothing was invented to fill space.
- The private apps (Card Optimizer, Jobgrab, The Signal) are described but **not linked**, and carry
  no figures, no personal data and no host paths. Don't add links — they sit behind Cloudflare
  Access and a link would only ever produce a login wall for a recruiter.
- Kubrix is described as an unofficial fan remake by a member of the original team, with the awards
  credited to Team Whiteboard & Markers rather than to one person. Keep that framing.
- **The Kubrix awards and credits come from the official DigiPen game gallery** (games.digipen.edu),
  not from the repo README, which lists only the grand prize. Both the award names and the nine
  names-with-roles are reproduced as that gallery displays them, so don't "tidy" them: the gallery
  shows "Sing Tan" (Jasman), and the roles are its wording, not ours. The official blurb is quoted
  and attributed. If the gallery entry ever changes, `src/data.mjs` → `PROJECTS.kubrix.awards` /
  `.credits` is the only place to edit.
- Camp Nightfall links to the site root only. **Never link `/host`** — it is the operator panel and
  is going behind Cloudflare Access.
